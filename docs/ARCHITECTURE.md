## 2. 模块依赖关系

```
config  ← 全局读取配置
   │
   ├── db        ← 数据库连接（底层依赖）
   ├── storage   ← 存储驱动（层）
   │     │
   │     ├── fs           ← 文件业务逻辑（依赖 storage/db）
   │     ├── share        ← 分享系统（依赖 fs/db）
   │     ├── recycle      ← 回收站（依赖 fs/db）
   │     ├── search       ← 全文搜索（依赖 fs/db）
   │     ├── version      ← 文件版本（依赖 fs/db）
   │     └── integrity    ← 完整性校验（依赖 storage）
   │
   ├── auth      ← 认证模块（依赖 db）
   ├── api       ← HTTP 路由注册（依赖所有业务模块）
   ├── log       ← 审计日志（依赖 db）
   ├── plugin    ← 插件系统（依赖 fs, db）
   │
   └── pkg/webdav, pkg/sftp  ← 标准协议实现
```

## 3. 核心设计原则

1. **单向依赖**：上层依赖下层，避免循环依赖
2. **接口隔离**：存储驱动、搜索、插件均定义抽象接口，实现可替换
3. **无状态 API**：基于 JWT 认证，API 层无状态，便于横向扩展
4. **异步后台**：完整性校验、搜索索引等耗时操作通过内置任务队列异步执行
5. **可观测**：所有关键操作记录审计日志
